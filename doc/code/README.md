## Сцены
Для игровых объектов мы максимально используем сцены. 
Их удобней использовать для визуального редактирования (перетаскивания и настройки).
Различные флаги или настройки одних и тех же объектов тоже необходимо делать настраиваемыми из визуального редактора Godot.
Важно делать сцены переиспользуемыми. 
Например, если мы хотим сделать стул - лучше сделать абстрактную основу и менять ей спрайт в визуальном редакторе для финального отображения. Подобный подход хочется использовать и для других игровых объектов.

Для больших сцен, которые могут перегородить игрока и сделать его невидимым (закрытым другим объектом) нужно добавить `TransparencyArea`. 
Банальный пример: стены, камин, большой шкаф и т.д. 
Для небольших объектов зону прозрачности нужно делать так же небольшой, совпадающей с размером объекта, но находящейся немного за объектом (там, где игрока будет скрывать).
Зона прозрачности не должна быть шире самого объекта. Не стоит ее добавлять не небольших сцен, за которыми игрока и так отлично видно.

## Структура кода
При создании новой локации (`level`), мы используем следующую структуру:
	- `scenes`
		- `levels`
			- `<new-level-name-folder>`
				- `<new-level-name>.tscn`
				- `<inner-scene>.tscn`
				...
	- `scripts`
		- `levels`
			- `<new-level-name-folder>`
				- `<new-level-name>.gd`
				- `<inner-scene>.gd`
				...

Если сцену или скрипт можно переиспользовать для других сцен / скриптов, можно рассмотреть перекладку скрипта / сцены в `core`.

## Нейминг
Как нельзя называть сцены / обекты:
	- `Collision0`, если у сцены нет других `Collision`, индексирование имеет смысл только в случаях, когда одинаковых сцен / объектов много
	- `Shape2D` - 2D окончание не используем, вся игра сделана в 2D, это очевидная информация
