# WineMaker

Godot 4.6, GDScript, 2D, Forward+. Базовые компоненты для новой игры.
Результат ревизии каждого оставленного и удалённого файла — в [docs/CORE_AUDIT.md](docs/CORE_AUDIT.md).

## Запуск

Открыть `project.godot` и нажать F5. Минимальный bootstrap открывает пустой
Level с персонажем. Для сети используется общий `NetworkSession`:

```sh
# Host
/Applications/Godot.app/Contents/MacOS/Godot --path . -- --host --port=7777 --name=Host

# Client
/Applications/Godot.app/Contents/MacOS/Godot --path . -- --join=127.0.0.1 --port=7777 --name=Guest
```

Это же API доступно через `NetworkSession.start_local()`, `host()`, `join()`
и `close()`. Сигналы `started`, `failed`, `disconnected` позволяют подключить
будущий интерфейс. `scripts/app.gd` — минимальная точка запуска без игрового меню.
Мир: `scenes/levels/main.tscn`; начальный Level назначается через `spawn_level`.

WASD — движение, E — взаимодействие, Q — поднять/разместить предмет.
В bootstrap F5 запрашивает сохранение, Esc закрывает приложение.
Во время диалогового сеанса Esc завершает разговор.

## Основа

- `Player`, `CharacterSprite`: управление, камера, посадка, перенос предмета,
  слои внешности и синхронизация кадров. Исходный визуальный стиль сохранён
  в каталоге спрайтов и цветов; генерация внешности не привязана к группам образов.
- `Seat`, `Draggable`, `DropPlace`, `Interactable`, `Switch`: общие взаимодействия,
  занятость и размещение без предметных моделей, картинок и звуков.
- `Door`: серверное открытое/закрытое состояние, проверка досягаемости и назначаемые
  коллизии `blockers`. Внешнее представление подключается к `state_changed`.
- `Room`, `Level`: геометрия, границы, навигация, локальная прозрачность,
  камера, точки появления и контекст игроков.
- `NPC`, `NPCRoute`, `NPCManager`, `NPCProfile`: серверное движение, расширяемые
  маршруты, управляемый спавн и сохранение внешности популяции.
- `NPCConversation`: эксклюзивный сетевой сеанс. Есть проверка расстояния и
  видимости, приостановка NPC, блокировка ввода участника и освобождение при выходе.
  Содержание и интерфейс подключаются через `started(player)` и `ended`;
  завершение — `close()`. Тем, раундов, оценок ответов и очков отношений нет.
- `WorldTime`: синхронизируемые часы, скорость, пауза и `time_changed`.
- `LightSource`: серверное состояние света и назначаемые `light_sources` /
  `glow_sprites`. Освещение мира и расписания задаёт будущая игровая реализация.
- `SaveGraph`, `WorldSave`, `SaveManager`: снимки объектов, проверка данных,
  атомарная запись, чтение и восстановление.

Движением игрока управляет его peer; внешностью и общим состоянием — сервер.
Игроки находятся под Main, NPC и динамические предметы — под Level.
Создаваемые сцены регистрируются в соответствующем `MultiplayerSpawner`.

## Сохранения

`WorldSave.request_save()` явно запрашивает снимок мира. Результат передаётся
через `saved(success)`, восстановление — через `restored(player)`.
Время записи, интерфейс, автосохранение и удаление старых файлов выбирает игра.
Данные располагаются в Godot `user://saves` проекта WineMaker.
Сохранение можно подготовить через `SaveManager.prepare_load(file_name)`
перед созданием мира; bootstrap принимает `--load=имя_файла.save`.

Объекты подключаются к сохранению через группу `saveable`, `get_save_data()`
и `apply_save_data()`. Сохраняется мир, часы, персонаж хоста и внешность популяции NPC;
гости и активные сеансы взаимодействия остаются временными.

## Ассеты и проверки

Оставлены спрайты персонажей и одежды, два шейдера окраски и иконка проекта.
Nearest-фильтрация, pixel snapping, Y-sort и опорная точка персонажа у ног сохранены.

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --editor --path . --quit
```

На других системах подставить свой путь к Godot.
